# Outbox relay: самопланирующаяся задача, delivered_at коммитится вместе с пачкой

`django.tasks` не имеет планировщика: задача выполняется, когда её поставили в очередь. Relay
должен работать постоянно, не требуя cron и брокера (ADR-0005).

Relay выполняет один проход и в конце сам ставит следующий через `run_after`. Внутри прохода
пачка событий берётся с `select_for_update(skip_locked=True)`, потребитель вызывается для каждого,
`delivered_at` ставится одним `UPDATE` перед коммитом. Альтернатива, отмечать каждое событие сразу
после доставки отдельной транзакцией, сужает окно повторов, но снимает блокировку строки между
доставкой и отметкой, и два relay могли бы доставить одно событие одновременно. Блокировка до
коммита важнее редких повторов: повтор потребитель всё равно обязан переживать (at-least-once).

## Consequences

- Падение между доставкой и коммитом даёт повторную доставку всей пачки; потребитель дедуплицирует
  по `event_id`.
- Исключение потребителя откатывает пачку; «ядовитое» событие блокирует события за ним, пока
  потребитель его не примет. Разбор таких событий вне этого решения.
- Порядок по `sequence` гарантирован внутри пачки; между параллельными relay порядка нет
  (см. `docs/outbox.md`).
- Запуск двух цепочек relay безвреден, но лишний; стартовая команда `start_outbox_relay` не
  проверяет, есть ли уже цепочка.
