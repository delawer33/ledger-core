# Фоновые задачи идут через django.tasks с бэкендом в базе, без брокера

Ядру нужны периодические процессы: истечение холдов, relay outbox,
reconciliation. Django 6 приносит стандартный интерфейс `django.tasks`, но
встроенные бэкенды только для разработки (немедленный и dummy). Постоянный
бэкенд на таблице в Postgres даёт пакет `django-tasks-db`: очередь живёт в той
же базе, что и данные, и воркер (`db_worker`) берёт задачи с блокировками
строк. Отдельный брокер (Redis, RabbitMQ, Celery) для трёх задач в одном
сервисе добавил бы компонент, который надо поднимать, мониторить и
сверять с базой.

Выбран `django-tasks-db` вместе с `django.tasks`, а не Celery: интерфейс
стандартный и переезд на другой бэкенд не меняет код задач. Цена выбора:
пропускная способность очереди ограничена базой, что для этих задач
приемлемо.

## Consequences

- Таблицы очереди появляются в миграциях приложения `django_tasks_db`.
- Задачи пишутся идемпотентными: доставка at-least-once, как и у outbox.
- Если очередь станет узким местом, бэкенд меняется настройкой `TASKS`.
