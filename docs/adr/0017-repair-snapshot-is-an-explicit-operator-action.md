# Снапшот чинит только явная команда repair_snapshot, close_incident проверяет результат

QA: `close_incident` ставил снапшоту `trusted=True`, не сверяя его с пересчётом.
Снапшот 889 при реальных 112 после закрытия инцидента снова доверенный, перевод
на 500 прошёл, liability ушёл в минус. Дыра из ADR-0015 открывалась заново.

Выбрано:

- `close_incident` под блокировкой счёта (та же, что у posting engine)
  сравнивает снапшот с `SUM(Entry)`. При расхождении отказ с кодом
  `snapshot_still_diverges` (422), инцидент остаётся открытым, снапшот
  недоверенным.
- Починка это отдельное действие `repair_snapshot(incident_id, note)` и команда
  `manage.py repair_snapshot <id> --note`. Под блокировкой счёта оно пишет в
  снапшот пересчёт, а в Incident: `repaired_from`, `repaired_to`,
  `repaired_at`, `repair_note`. Заметка обязательна, закрытый инцидент
  отклоняется. Доверие repair не возвращает: это делает `close_incident`.
- ADR-0003 не нарушен: ничто не чинит снапшот само, ни сверка, ни проводка.
  Перезапись происходит только по команде человека и оставляет след.

## Consequences

- Закрытие инцидента двухшаговое: repair, затем close. Забытый repair
  не превращается в тихую потерю доверия к деньгам.
- Параллельная проводка во время repair ждёт блокировку счёта, поэтому
  снапшот после repair равен пересчёту с учётом всех проводок.
- Миграция 0005 добавляет четыре nullable-поля в Incident.
