# Доменные ошибки несут машинный код правила

Нарушение инварианта в ядре это типизированное исключение `LedgerError` с полями `code`
(стабильный идентификатор правила, например `insufficient_funds`), `detail` (текст для человека) и
`status`. Один обработчик в `api.py` превращает его в ответ `{"code", "detail"}`: 422 для нарушений
инвариантов, 404 для отсутствующих сущностей, 409 для конфликта идемпотентности, 400 для пропущенных
обязательных заголовков.

Клиенты ветвятся по `code`, а не по тексту или статусу: статус 422 один на десяток разных правил.
Ошибки валидации формы запроса (не целое число, неизвестный вид операции) отдаёт сам django-ninja
своим форматом 422; это ошибки клиента, а не правила предметной области.

Исключение бросается до первой записи, а проверки идут внутри `transaction.atomic`, поэтому
отклонённая операция не оставляет следов. Новое правило добавляет подкласс с новым кодом; существующие
коды не переименовываются.
