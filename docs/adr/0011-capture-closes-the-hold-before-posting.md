# Capture закрывает холд до проводки, в одной транзакции БД

Posting engine проверяет запрет минуса по Available Balance, то есть Posted минус активные холды.
Если capture сначала проводит транзакцию, сам захватываемый холд ещё активен и уменьшает Available:
capture на всю сумму холда счёта без других денег отвергся бы как «недостаточно средств».

Поэтому capture в одной `transaction.atomic` блокирует строку холда, ставит статус `captured` и только
потом вызывает posting engine. Статус сохраняется в БД до проводки (`save`), а не только
ставится в памяти: posting engine читает активные холды запросом и иначе всё ещё вычитал бы этот холд. Холд перестаёт считаться заморозкой, а проверка видит остальные
активные холды. Отказ проводки (нет счёта-получателя, минус) откатывает и смену статуса: холд
остаётся активным. Порядок блокировок: холд, затем счета по возрастанию id; place блокирует только
счёт, release и expire только холд, поэтому цикла нет.

Частичный capture не хранит остаток: холд закрывается целиком, списанная сумма живёт в Entry
транзакции `hold_capture`, а несписанная просто перестаёт быть заморожена. Expire выбирает по
статусу и `expires_at`, пачками `skip_locked`; до запуска задачи просроченный холд ещё активен и
замораживает сумму. Периодичность запуска задачи `expire_holds` задаёт развёртывание (ADR-0005).

## Consequences

- Холд не меняет Posted Balance; только capture двигает деньги, и только через posting engine.
- Expire и release оба пишут событие `hold.released`; причина в поле `reason`.
