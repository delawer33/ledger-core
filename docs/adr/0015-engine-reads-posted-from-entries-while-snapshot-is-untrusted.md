# Пока снапшот недоверенный, движок берёт Posted из Entry

QA нашёл дыру: чтение баланса пересчитывало Posted из Entry при открытом
Incident (ADR-0003), а posting engine и place hold читали испорченный
снапшот. Снапшот, завышенный на 777, пропустил перевод сверх реальной суммы,
и счёт ушёл в минус. Сама сверка этого не увидела: она не проверяла знак
баланса.

Выбрано:

- Одна функция `balances.service.posted_amount` для движка, холдов и
  эндпоинта чтения: доверенный снапшот читается как есть (быстрый путь, без
  запросов к Entry), недоверенный заменяется пересчётом `SUM(Entry)`.
  `available_amount` строится на ней, формулы Available в одном месте.
  Пересчёт идёт под блокировкой счёта, которую движок уже держит, поэтому
  читает согласованную картину. Capture и reversal идут через движок и
  получают то же поведение. Проверка диапазона bigint тоже берёт Posted
  отсюда.
- Снапшот по-прежнему не чинится. Проводка на недоверенном счёте продолжает
  обновлять его дельтой и не меняет `trusted`: расхождение не «легализуется»
  и не исчезает, пока оператор не вызовет `close_incident`. Дельта на
  испорченное значение даёт то же расхождение, которое видит сверка.
- Сверка открывает Incident и на отрицательный Posted у счёта типа liability
  или asset (`expected` и `actual` пишутся как обычно, они могут совпасть),
  и помечает снапшот недоверенным, как при расхождении. Revenue, expense и
  equity в минус уходить могут. Холды выше Posted по-прежнему только в
  логе (ADR-0010): это нарушение Available при целом снапшоте, а не
  отрицательный Posted.

## Consequences

- Цена: пока открыт Incident, каждая проводка на счёте делает один
  `SUM` по Entry счёта. Доверенные счета платят только за чтение снапшота.
- Проверка диапазона теперь читает снапшот по счёту отдельным запросом
  вместо одного пакетного.
