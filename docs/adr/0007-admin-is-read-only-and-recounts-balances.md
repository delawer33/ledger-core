# Админка только для чтения и считает балансы из Entry

Django Admin нужна, чтобы посмотреть, что внутри ядра, без SQL. Любая правка
через неё обошла бы posting engine: изменила бы данные без Entry, без
BalanceSnapshot и без Outbox Event. Поэтому у всех моделей запрещены add,
change и delete, для всех пользователей, включая суперпользователя
(`has_*_permission` возвращают False в общей базе `ReadOnlyModelAdmin`). Запрос
на изменение отвечает 403, а не скрывает кнопки.

Posted и Available в списке счетов считаются подзапросами по Entry и активным
холдам, а не берутся из BalanceSnapshot. Снапшот кэш и может разойтись с
правдой (это ловит reconciliation); админка, которой оператор верит при
разборе инцидента, не должна повторять ошибку кэша. Цена выбора: страница
списка делает группировку по Entry, что приемлемо для инструмента оператора, а
не для горячего пути.

Суперпользователя для dev создаёт `seed` из `DJANGO_SUPERUSER_*` (значения в
`.env.example`); при `ENVIRONMENT=production` он ничего не создаёт. Статику
админки отдаёт WhiteNoise прямо из установленных приложений
(`WHITENOISE_USE_FINDERS`), без шага collectstatic и отдельного веб-сервера.

## Consequences

- Каждая новая модель ядра регистрируется в админке через `ReadOnlyModelAdmin`.
- Исправить данные через админку нельзя: ошибка исправляется Reversal, закрытие
  инцидента остаётся отдельной командой (ADR-0003).
- Тесты админки проверяют 403 на POST в change-view и вычисляемые балансы.
