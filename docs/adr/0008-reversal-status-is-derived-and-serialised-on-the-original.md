# Статус reversal вычисляется по ссылке и сериализуется блокировкой исходной транзакции

У Transaction нет поля статуса. «Reversed» означает, что другая транзакция указывает на неё через
`reversal_of`; `GET /transactions/{id}` отдаёт `reversed_by` запросом по этой ссылке. Хранимый флаг мог
бы разойтись с проводками, вычисляемое значение разойтись не может.

Reversal проходит через `post_transaction`, поэтому подчиняется тем же инвариантам. Если счёт уже
потратил деньги и отмена увела бы его в минус, reversal отвергается правилом `insufficient_funds`.
Автоматического «довзыскания» нет: компенсировать дыру решает вызывающая система отдельной операцией.

Повторный reversal ловится дважды. `reverse_transaction` берёт `select_for_update` на исходную
транзакцию, поэтому параллельные запросы идут по очереди, и второй получает
`transaction_already_reversed` (422). Уникальный частичный индекс `transaction_reversed_once` остаётся
страховкой на уровне БД. Reversal сам можно отменить: это обычная транзакция с `reversal_of`, цепочка
ограничена тем, что каждую транзакцию отменяют не более одного раза.
