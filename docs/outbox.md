# Контракт Outbox Event

Это публичный контракт ядра: потребитель получает события в таком виде и может на него
рассчитывать. Всё остальное внутри ядра может меняться.

## Поля события

| Поле | Тип | Смысл |
|---|---|---|
| `event_id` | UUID | Идентификатор события. По нему потребитель отбрасывает дубликаты. |
| `sequence` | целое, монотонно растёт | Порядковый номер события в outbox. По нему потребитель упорядочивает события. |
| `type` | строка | Вид факта, например `transaction.posted`. |
| `payload` | JSON-объект | Данные факта; состав зависит от `type`. |
| `occurred_at` | дата и время (UTC) | Когда событие записано, то есть когда факт попал в базу. |

Событие сообщает, что произошло, и никогда не просит что-то сделать.

### `transaction.posted`

```json
{
  "transaction_id": 42,
  "kind": "transfer",
  "reversal_of": null,
  "posted_at": "2026-10-18T12:00:00+00:00",
  "entries": [{"account_id": 1, "amount": -100}, {"account_id": 2, "amount": 100}]
}
```

`amount` в минорных единицах валюты, со знаком (ADR-0001).

## Гарантии

- **Событие есть тогда и только тогда, когда есть факт.** Событие пишется в той же транзакции БД,
  что и проводка. Откат проводки откатывает и событие.
- **At-least-once.** Relay доставляет событие, затем помечает его `delivered_at`. Если relay упал
  между этими шагами, событие уйдёт повторно. Потребитель обязан быть идемпотентным по `event_id`.
- **Порядок по `sequence`.** Один relay отдаёт события пачками в порядке возрастания `sequence`.
  Несколько relay одновременно берут непересекающиеся пачки (`skip_locked`), поэтому глобальный
  порядок между пачками разных relay не гарантируется. Потребитель, которому он нужен, сортирует
  по `sequence` сам.
- **Повтор тоже в порядке.** Повторно доставленное событие приходит с тем же `event_id` и тем же
  `sequence`.

## Как работает relay

Задача `django.tasks` `ledger.outbox.tasks.relay_outbox` за один проход:

1. В транзакции берёт до 100 недоставленных событий по `sequence` с
   `select_for_update(skip_locked=True)`.
2. Вызывает потребителя для каждого события.
3. Ставит `delivered_at` и коммитит.
4. Ставит в очередь следующий проход через `OUTBOX_RELAY_INTERVAL_SECONDS` (по умолчанию 5).

Первый проход ставит `python manage.py start_outbox_relay`, выполняет воркер
`python manage.py db_worker` (ADR-0005). Если потребитель бросил исключение, пачка откатывается
целиком и уходит заново на следующем проходе.

## Демо-потребитель

`ledger.outbox.consumer.record_delivery` пишет событие в `DeliveredEvent`. Уникальность по
`event_id` отбрасывает дубликат. Потребитель живёт в том же процессе и той же базе (ADR-0002:
брокера нет), поэтому его запись откатывается вместе с пачкой; настоящий внешний потребитель так
не защищён, и дедупликация по `event_id` нужна ему обязательно.
